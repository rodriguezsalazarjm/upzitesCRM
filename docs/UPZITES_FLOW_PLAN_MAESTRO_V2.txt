UPZITES FLOW — PLAN MAESTRO DE PRODUCTO
Versión congelada de planificación
Fecha: 29-09-2026

OBJETIVO GENERAL
Construir Upzites Flow como una plataforma SaaS multi-workspace capaz de centralizar ventas, atención, automatizaciones, IA, comercio digital, publicación social y operación diaria de distintos tipos de negocio, con una experiencia adaptativa por rubro.

REGLA DE CONTROL
Cada bloque tiene un “HITO DE FINALIZACIÓN”. Cuando ese hito se cumpla y las pruebas estén verdes, el bloque se considera CONCLUIDO y no se vuelve a ampliar salvo que aparezca un bug, una exigencia legal/API o una decisión explícita de producto.

37. QUOTE STUDIO / GENERADOR DE COTIZACIONES PDF
==================================================

OBJETIVO
Permitir que cada empresa cree cotizaciones profesionales, rápidas y adaptadas a su forma de vender, sin obligarla a usar una plantilla rígida ni convertir Upzites Flow en un software de diseño complejo.

PRINCIPIO DE PRODUCTO
NO construir un editor libre tipo Canva.

La solución debe ser:
- modular;
- rápida;
- segura;
- fácil de mantener;
- adaptable por rubro;
- suficientemente personalizable para verse propia de cada marca.

MODELO PROPUESTO
Usar un sistema de PLANTILLAS POR BLOQUES.

Cada workspace puede tener una o varias plantillas de cotización.

Ejemplos:
- Cotización estándar.
- Proyecto web.
- Instalación técnica.
- Servicio mensual.
- Productos.
- Cotización rápida.
- Propuesta premium.

Cada plantilla se construye con bloques reordenables, no con posicionamiento libre por píxeles.

BLOQUES DISPONIBLES
- Logo / identidad.
- Encabezado.
- Datos de la empresa.
- Datos del cliente.
- Número de cotización.
- Fecha.
- Fecha de vencimiento.
- Ejecutivo responsable.
- Título.
- Introducción.
- Tabla de productos/servicios.
- Subtotal.
- Descuento.
- Impuestos.
- Costos adicionales.
- Total.
- Forma de pago.
- Condiciones comerciales.
- Validez de la oferta.
- Plazos de entrega.
- Notas.
- Términos.
- Firma.
- CTA / datos de contacto.
- Footer.

PERSONALIZACIÓN VISUAL
Brand Kit por workspace:

- Logo.
- Nombre comercial.
- Colores principales.
- Color de acento.
- Tipografía de títulos.
- Tipografía de cuerpo.
- Tamaños predefinidos.
- Bordes.
- Espaciado.
- Estilo de tablas.
- Estilo de encabezado/footer.

TIPOGRAFÍAS
Para mantener el sistema simple:
- catálogo curado de tipografías soportadas;
- fuentes web seguras / Google Fonts cuando corresponda;
- evitar inicialmente uploads arbitrarios de fuentes.

No permitir CSS arbitrario del cliente.

EDITOR DE PLANTILLA
Experiencia recomendada:

IZQUIERDA:
bloques disponibles.

CENTRO:
preview en vivo de la cotización.

DERECHA:
propiedades del bloque seleccionado.

Acciones:
- agregar bloque;
- eliminar;
- arrastrar/reordenar;
- duplicar;
- mostrar/ocultar;
- editar estilos permitidos;
- guardar plantilla;
- duplicar plantilla.

NO usar canvas de posicionamiento libre en la primera versión.

MOTOR DE CÁLCULO
Debe ser muy rápido para usuarios que generan varias cotizaciones por día.

Cada línea puede incluir:
- producto/servicio;
- descripción;
- cantidad;
- unidad;
- precio unitario;
- descuento;
- impuesto;
- subtotal.

Cálculo automático:
cantidad × precio
− descuento
+ impuesto
+ cargos
= total.

Debe admitir:
- CLP.
- USD.
- moneda definida por workspace.
- precios con o sin impuesto.
- descuento por línea.
- descuento global.
- IVA configurable cuando corresponda.

NO permitir fórmulas arbitrarias ejecutables.

Si más adelante se necesitan fórmulas:
usar un conjunto limitado de operaciones declarativas y seguras.

CATÁLOGO REUTILIZABLE
Para acelerar la creación:

- guardar servicios frecuentes;
- guardar productos frecuentes;
- precio sugerido;
- descripción estándar;
- unidad;
- impuesto;
- categoría.

Ejemplo:

“Diseño web corporativo”
→ $XXX
→ descripción precargada.

El usuario puede modificarlo en una cotización concreta sin alterar el catálogo.

DATOS DEL CLIENTE
Reutilizar:
- Contact.
- Company.
- Opportunity.

Al crear una cotización:
seleccionar contacto/empresa
→ datos se completan automáticamente.

También permitir cliente rápido sin tener que abandonar la cotización.

WORKFLOW DE COTIZACIÓN
Estados iniciales:

DRAFT
READY
SENT
VIEWED
ACCEPTED
REJECTED
EXPIRED
CANCELLED

Futuro:
PARTIALLY_PAID
PAID

ACCIONES RÁPIDAS
- Nueva cotización.
- Duplicar.
- Editar.
- Generar PDF.
- Descargar PDF.
- Copiar link.
- Enviar por email.
- Enviar por WhatsApp.
- Marcar aceptada/rechazada.
- Convertir en nueva versión.

NUMERACIÓN
Por workspace.

Ejemplo:
COT-2026-0001

Configurable:
- prefijo;
- correlativo;
- año;
- reinicio anual opcional.

PDF
Generación server-side.

Requisitos:
- resultado determinístico;
- mismo diseño en preview y PDF;
- buena impresión A4;
- saltos de página seguros;
- tablas que continúan correctamente;
- logo e imágenes optimizadas;
- tipografías soportadas;
- no depender del navegador del cliente.

VERSIONADO
Cuando una cotización se envía:

guardar un snapshot de:
- líneas;
- precios;
- descuentos;
- impuestos;
- textos;
- datos cliente;
- branding/template relevante.

Editar posteriormente debe crear una nueva versión o dejar claro que el documento enviado era una versión anterior.

Esto evita que una cotización histórica cambie porque el usuario cambió:
- logo;
- plantilla;
- precio;
- términos.

COTIZACIÓN DESDE PIPELINE
Desde Opportunity:

[ Crear cotización ]

Debe precargar:
- cliente;
- empresa;
- oportunidad;
- ejecutivo.

La cotización queda relacionada con la Opportunity.

FUTURO
Cotización aceptada
→ avanzar pipeline automáticamente.

ENVÍO
Desde la propia cotización:

[ Enviar por email ]
[ Enviar por WhatsApp ]
[ Descargar PDF ]
[ Copiar enlace ]

El envío puede adjuntar PDF y además incluir un link web seguro.

PÁGINA PÚBLICA OPCIONAL
/quote/[token]

Puede mostrar:
- cotización;
- descargar PDF;
- aceptar;
- rechazar;
- dejar comentario.

No es obligatoria para el MVP, pero la arquitectura debe permitirla.

MÉTRICAS
- creadas;
- enviadas;
- vistas;
- aceptadas;
- rechazadas;
- vencidas;
- tasa de aceptación;
- valor cotizado;
- valor aceptado;
- tiempo medio de aceptación.

ADAPTACIÓN POR RUBRO
El sistema se adapta principalmente mediante PLANTILLAS, no mediante código distinto por cliente.

SERVICES:
servicios + horas + proyectos.

INSTALACIONES:
materiales + mano de obra + metros/unidades.

AGENCIA:
packs + mensualidades + extras.

ECOMMERCE/B2B:
productos + cantidades + descuentos.

Así evitamos programar un cotizador diferente para cada industria.

SEGURIDAD
- Workspace isolation.
- PDF solo accesible por usuario autorizado o token público seguro.
- Totales calculados server-side.
- No confiar en importes manipulados por cliente.
- Auditoría de envío/aceptación.
- Historial de versiones.

HITO DE FINALIZACIÓN:
Un OWNER/ADMIN crea una plantilla con su logo, colores y tipografías; genera una cotización con varias líneas, cantidades, descuentos e impuestos; los totales se calculan automáticamente; genera un PDF profesional; lo envía desde Upzites Flow; y puede duplicar la cotización para crear otra en menos de un minuto sin tocar código.

ESTADO: PENDIENTE.

38. EMAIL CLIENT LITE / CORREO DENTRO DE UPZITES FLOW
==================================================

OBJETIVO
Permitir leer y enviar correos comerciales básicos desde Upzites Flow sin intentar reemplazar Gmail u Outlook.

ALCANCE
Mantenerlo deliberadamente simple.

DEBE PERMITIR
- Conectar una cuenta de correo.
- Ver Inbox.
- Ver enviados.
- Abrir un correo.
- Ver hilo/conversación.
- Redactar.
- Responder.
- Reenviar.
- Adjuntar archivos.
- Adjuntar una cotización PDF.
- Asociar correo a Contact.
- Asociar correo a Company.
- Asociar correo a Opportunity.
- Buscar por persona/asunto.
- Estado leído/no leído.
- Archivar.

NO CONSTRUIR INICIALMENTE
- Calendario.
- Contactos de Google/Microsoft completos.
- Reglas complejas.
- Filtros avanzados.
- Spam engine.
- Offline.
- Gestión completa de carpetas/labels.
- Firma visual avanzada.
- Cliente de correo equivalente a Gmail.

PROVEEDORES INICIALES
Preferencia:
- Gmail mediante OAuth/API.
- Microsoft 365 / Outlook mediante OAuth/Graph.

Futuro:
- IMAP/SMTP genérico si realmente es necesario.

SEGURIDAD
- OAuth.
- Tokens cifrados.
- Revocación.
- Scopes mínimos.
- Workspace isolation.
- Nunca almacenar passwords de correo.

INBOX UNIFICADO
Ruta sugerida:

Inbox
→ Conversaciones
→ WhatsApp
→ Instagram
→ Email

o filtro de canales dentro del Inbox existente.

Cada hilo debe mostrar claramente:
- canal;
- remitente;
- asunto;
- fecha;
- adjuntos;
- contacto relacionado.

CRM CONTEXT
Al abrir un email de una persona conocida mostrar lateralmente:
- contacto;
- empresa;
- oportunidad;
- últimas actividades;
- cotizaciones;
- pedidos cuando corresponda.

COTIZACIONES
Desde Quote Studio:

[ Enviar por email ]

Debe abrir un compose precargado con:
- destinatario;
- asunto;
- mensaje;
- PDF adjunto;
- opcionalmente link público.

Al enviarlo:
- cotización pasa a SENT;
- se registra actividad;
- email queda en thread;
- queda relacionado al Contact/Opportunity.

RESPUESTAS
Si el cliente responde:
- aparece en Inbox;
- queda relacionada con el contacto;
- puede notificar al responsable;
- puede actualizar “última actividad”.

AUTOMATIZACIONES FUTURAS
Eventos útiles:
- email recibido;
- email respondido;
- cotización enviada;
- cotización sin respuesta X días.

Acciones:
- enviar email;
- crear tarea;
- notificar;
- follow-up.

IMPORTANTE
Separar tres conceptos:

1. PLATFORM TRANSACTIONAL EMAIL
Invitaciones, password reset, seguridad.

2. TENANT TRANSACTIONAL EMAIL
Entregas, pedidos, notificaciones automáticas.

3. USER MAILBOX
Correo humano del cliente: leer, responder y enviar desde su propia cuenta.

No mezclar credenciales ni quotas entre ellos.

HITO DE FINALIZACIÓN:
Un usuario conecta su Gmail o Microsoft 365, recibe y lee un correo dentro de Flow, responde desde Flow, envía una cotización PDF desde Quote Studio y toda la conversación queda asociada correctamente al contacto y oportunidad.

ESTADO: PENDIENTE.

1. Un cliente pueda registrarse/invitarse.
2. Configure su negocio sin ayuda técnica.
3. Conecte al menos WhatsApp o Instagram.
4. Cree un producto/servicio desde UI.
5. Entrene su IA.
6. Active una automatización.
7. Reciba un lead.
8. La IA pueda atenderlo.
9. Se pueda generar una venta o conversión.
10. El sistema pueda verificar pago cuando aplique.
11. Entregue el producto automáticamente cuando aplique.
12. El dashboard refleje el resultado.
13. El cliente pueda gestionar su equipo.
14. El workspace adapte la experiencia a su rubro.
15. Los fallos principales sean observables.
16. Todo lo anterior pueda hacerse sin tocar código o base de datos.
17. Un negocio de servicios pueda crear, calcular, generar y enviar una cotización PDF profesional desde Flow.
18. Un usuario pueda leer y responder correos básicos desde su cuenta conectada y relacionarlos con contactos/oportunidades.
